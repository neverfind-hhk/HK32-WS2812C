## 引脚提醒
TSSOP20，可用 GPIO 16 个：PD4 / PD5(SWDIO) / PD6 / NRST / PA1 / PA2 / PA3 / PB4 / PB5(SWCLK) / PC3 / PC4 / PC5 / PC6 / PC7 / PD1 / PD2 / PD3。**没有 PC13**，GPIOC 只有 PC3~PC7。

**调试口（SWD）**：PD5 = SWDIO / PB5 = SWCLK
不要拿它驱动 LED，否则下次烧录连不上。

## 备注
库用的是双芯片版 SPL_PLUS，本芯片用不到的模块（如 C 系列没有的 BEEP/EEPROM/I2S）
会自动走条件编译分支，**无需手动摘文件**。

## SPI1（已配好）

驱动在 `User/spi1.c` / `User/spi1.h`，main() 里已调用 `SPI1_Init()`。

| 信号 | 引脚 | 配置 |
|---|---|---|
| SCK | **PC5（脚15）** | AF2 |
| MOSI | **PC6（脚16）** | AF2 |
| MISO | **PC7（脚17）** | AF2 |
| CS | **PC4（脚14）** | 普通 GPIO 推挽输出（软件片选，低有效） |

默认参数：**主模式、8 位、模式 0（CPOL=0/CPHA=0）、MSB 先行、软件 NSS、4 MHz**（32 MHz ÷ 8）。

```c
SPI1_Init();                          /* 初始化 */
SPI1_CS_LOW();                        /* 选中从设备 */
id = SPI1_ReadWriteByte(0x9F);        /* 全双工收发一个字节 */
buf[0] = SPI1_ReadWriteByte(0xFF);
SPI1_CS_HIGH();                       /* 释放 */
```

接不同从设备时要改的通常只有两处：`spi1.h` 里的 `SPI1_PRESCALER`（波特率）和
`spi1.c` 里的 `SPI_CPOL` / `SPI_CPHA`（模式）。**从设备手册给的最高 SCK 一定要遵守。**

### 引脚选择的依据

依据《HK32F030M 数据手册》表 6-5 引脚复用功能表，SPI 的复用编号是 **AF2**。
TSSOP20 封装上没有 PA4~PA7，所以用不了 STM32 那套默认 SPI 引脚。
可用的组合只有下面这些：

| 功能 | 可用引脚 |
|---|---|
| SCK | PA2(脚6)、**PC5(脚15)**、PD3(脚20) |
| MISO | PB4(脚12)、**PC7(脚17)**、PD6(脚3) |
| MOSI | **PC6(脚16)**、PD2(脚19)、PD4(脚1) |
| NSS | PA3(脚10) —— **PB5 是 SWCLK，不能占用** |

PC5/PC6/PC7 正好是脚 15/16/17 连续排列，所以选了这一组。
想换引脚就改 `spi1.h` 顶部的宏和 `spi1.c` 里的 `GPIO_PinSource`/`GPIO_AF_2`。

## WS2812C-2020 灯带（已配好）

数据线走 **PC6（脚16 = SPI1_MOSI）**，驱动在 `User/ws2812.c` / `ws2812.h`。
target 灯珠：**WorldSemi WS2812C-2020-V6**，共 **2 颗**。

### ⚠️ WS2812C 的时序和 WS2812B 不一样

按《WS2812C-2020 Datasheet》第 4 页 Data Transfer Time：

| 参数 | WS2812C-2020 | (参考) WS2812B |
|---|---|---|
| T0H | **220 ~ 380 ns** | 250 ~ 550 ns |
| T0L | **580 ~ 1000 ns** | 700 ~ 1000 ns |
| T1H | **580 ~ 1000 ns** | 650 ~ 950 ns |
| T1L | **580 ~ 1000 ns** | 300 ~ 600 ns |
| RES | > 280 µs | > 280 µs |

**用 WS2812B 的参数配 WS2812C 会花屏** —— 典型后果是 T0H 偏长（被认成 1）、
T1L 偏短（低于 580 ns 下限）。而且 C 版的 0 码周期（800~1380 ns）与 1 码周期
（1160~2000 ns）**并不相同**，SPI 是固定位宽，只能取交集，即 **T = 1250 ns**。

### 编码方案：16 MHz + 20 bit

```
SPI = 32MHz ÷ 2 = 16MHz，1 个 SPI bit = 62.5 ns
每个 WS2812 位用 20 个 SPI 位 → 合计 1250 ns
```

| 数据 | 20bit 波形 | 常量 | T_HIGH | T_LOW | 余量 |
|---|---|---|---|---|---|
| **0** | `11111`+15×`0` | `0x0F8000` | **312.5 ns** | **937.5 ns** | 上限余 93/68ns |
| **1** | `1111111111`+10×`0` | `0x0FFC00` | **625.0 ns** | **625.0 ns** | 下限余 45ns |

四个参数全部合规且余量充足。24 bit × 20 = 480 bit = **60 字节 / LED**。

> 为什么不用 8 MHz + 10 bit？也能凑出 1250 ns，但量化步进 125 ns 太粗，
> T0H 只能取 250 ns（贴近下限）或 375 ns（离 380 上限只剩 5 ns）。
> 16 MHz 的 62.5 ns 步进能把 T0H 放在 312.5 ns，更居中。

### 为什么不是 DMA

HK32F030 全系列没有 DMA（四个系列的 SVD 里 DMA 数量都是 0），SPI 的 FIFO 也只有
4 层（约 8 µs 缓冲），中断一旦延迟超时就会断流。所以用**阻塞发送**：
波形绝对连续，代价是发送期间占用 CPU —— 2 颗灯珠约 **60 µs**，基本无感。

### 用法

```c
WS2812_Init();                          /* 内部会调用 SPI1_Init()，16MHz */

WS2812_SetPixel(0, 255, 0, 0);          /* 第0颗：红（按 RGB 传，内部转 GRB）*/
WS2812_SetPixel(1, 0, 255, 0);          /* 第1颗：绿 */
WS2812_Show();                          /* 编码 + 阻塞发送 + 自动复位脉冲 */

WS2812_Fill(0, 0, 0); WS2812_Show();    /* 全灭 */
```

灯珠数量由 `ws2812.h` 的 `WS2812_LED_MAX`（当前 **2**）控制，改大即可带更多灯。

### 复位处理

发完一帧后把 MOSI 脚临时切成普通 GPIO 输出低电平保持 **300 µs**，再切回 SPI 复用。
不能只靠 SPI 空闲电平 —— SPI 关闭后引脚状态不确定，若最后一位恰好为高，
灯珠会锁存失败（表现为最后一颗颜色错乱）。

### 资源占用

| 项目 | 值 |
|---|---|
| 缓冲 | 2 LED × 3 B + 60 B = **66 B** |
| 每帧耗时 | 2 颗 ≈ **60 µs** |
| 实测 ROM | 3596 B / 16 KB（21.9%） |
| 实测 SRAM | 1200 B / 2 KB（58.6%） |
