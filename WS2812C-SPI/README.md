## 引脚提醒
TSSOP20，可用 GPIO 16 个：PD4 / PD5(SWDIO) / PD6 / NRST / PA1 / PA2 / PA3 / PB4 / PB5(SWCLK) / PC3 / PC4 / PC5 / PC6 / PC7 / PD1 / PD2 / PD3。**没有 PC13**，GPIOC 只有 PC3~PC7。

**调试口（SWD）**：PD5 = SWDIO / PB5 = SWCLK
不要拿它驱动外部器件，否则下次烧录连不上。

本工程实际占用：**PC5 = SCK，PC6 = MOSI（WS2812 数据线）**，PC4 = 软件片选（预留），PC7 未使用。

## SPI1

驱动在 `User/spi1.c` / `User/spi1.h`。**注意本工程的 SPI1 是为 WS2812 定制的**：
只发送、10 位帧。要接普通 SPI 从设备，请按下面「改回普通 8 位 SPI」一节调整。

| 信号 | 引脚 | 配置 |
|---|---|---|
| SCK | **PC5（脚15）** | AF2 |
| MOSI | **PC6（脚16）** | AF2 —— WS2812 数据线 |
| CS | **PC4（脚14）** | 普通 GPIO 推挽输出（软件片选，低有效，预留未用） |
| MISO | — | **不配置**，只发送模式不占引脚，PC7 可作它用 |

固定参数：**主模式、只发送（1Line_Tx）、10 位帧、模式 0（CPOL=0/CPHA=0）、
MSB 先行、软件 NSS、8 MHz**（32 MHz ÷ 4）。

### 为什么帧宽是 10 位，而不是 8 位

本芯片 SPI 的 `CR2.DS[3:0]` 是**数据位宽字段**（支持 4~16 位，标准库提供了
`SPI_DataSize_4b` ~ `SPI_DataSize_16b` 全部 13 个选项），**不是**常见的那种
只有 8/16 两档的 DFF 位。

设成 10 位后，**一次 SPI 发送 = 一个 WS2812 码**，10 bit ÷ 8 MHz = 1.25 µs，
正好等于 WS2812C 的位周期。

按 8 位字节发会出问题：一个 10 位的码必然跨在字节边界上。以 0 码
`1100000000` 为例，前 8 位在 byte N、后 2 位在 byte N+1。一旦 CPU 在字节
边界换填 FIFO 慢了一拍，MOSI 就会掉下来，把正在输出的高电平劈成两段。

> 实测证据：某帧里唯一一个 1 码的高电平位于 SPI 位 `[230..234]`，正好跨在
> byte28(`0x03`) / byte29(`0xE0`) 的边界（bit232）上，示波器上看得到
> **625 ns 被切成 250 ns + 375 ns**，整帧高脉冲从 48 个变成 49 个，
> WS2812 据此错位，第二颗灯收到错误的字节。

按码发之后，每个码的高电平都完整落在自己那一帧的开头，帧与帧之间
的空隙只会把**低电平**拉长。低电平拉长对 WS2812 无害（只要远小于 280 µs
复位门限），所以即使 CPU 偶尔慢一拍、甚至被中断打断，也**不可能**再破坏
高电平宽度。这是结构性保证，不是靠调优凑出来的。

### 接口

```c
SPI1_Init();                                   /* 初始化（10 位帧、8MHz） */

SPI1_WriteFrame(0x0300);                       /* 写一帧，不等待 */
SPI1_WaitDone();                               /* 等移位寄存器发完 */

SPI1_TransmitFrames(frames, 48);               /* 连续发 N 帧，内部自动等 BSY */
```

### 改回普通 8 位 SPI

1. `spi1.h` 里 `SPI1_DATA_BITS` 改 `8U`、`SPI1_DATA_SIZE` 改 `SPI_DataSize_8b`
2. 发送接口改成按字节：`SPI1_TransmitFrames(const uint16_t*)` 要换成
   `const uint8_t*` 版本（或直接用 `SPI1->DR = byte`）
3. 需要接收的话，还得把 `SPI_Direction_1Line_Tx` 改成 `SPI_Direction_2Lines_FullDuplex`
   并补上 MISO 引脚配置

### 引脚选择的依据

依据《HK32F030M 数据手册》表 6-5 引脚复用功能表，SPI 的复用编号是 **AF2**。
TSSOP20 封装上没有 PA4~PA7，所以用不了 STM32 那套默认 SPI 引脚。
可用的组合只有下面这些：

| 功能 | 可用引脚 |
|---|---|
| SCK | PA2(脚6)、**PC5(脚15)**、PD3(脚20) |
| MISO | PB4(脚12)、**PC7(脚17)**、PD6(脚3) |
| MOSI | **PC6(脚16)**、PD2(脚19)、PD4(脚1) |
| NSS | PA3(脚10) —— **PB5 是 SWCLK，不能占用** |

PC5/PC6/PC7 正好是脚 15/16/17 连续排列，所以选了这一组。

## WS2812C-2020 灯带

数据线走 **PC6（脚16 = SPI1_MOSI）**，驱动在 `User/ws2812.c` / `ws2812.h`。
目标灯珠：**WorldSemi WS2812C-2020-V6**，共 **2 颗**（`WS2812_LED_MAX`）。

### ⚠️ 供电要求

WS2812C-2020-V6 手册要求 **VDD = 3.7 ~ 5.3 V**，而本板是 3.3 V 系统。
3.3 V 供电时虽然多数情况能亮，但 LED 之间的级联信号（前一颗的 DO →
后一颗的 DI）高电平只有 2.5~2.7 V 左右，卡在后一颗 VIH(min)=2.7 V 的边缘。
**建议灯珠单独供 5 V**，`DIN` 仍由 MCU 的 3.3 V 直接驱动（VIH 只要 2.7 V，
够用，不需要电平转换）。

### ⚠️ WS2812C 的时序和 WS2812B 不一样

按《WS2812C-2020 Datasheet》第 4 页 Data Transfer Time：

| 参数 | WS2812C-2020 | (参考) WS2812B |
|---|---|---|
| T0H | **220 ~ 380 ns** | 250 ~ 550 ns |
| T0L | **580 ~ 1000 ns** | 700 ~ 1000 ns |
| T1H | **580 ~ 1000 ns** | 650 ~ 950 ns |
| T1L | **580 ~ 1000 ns** | 300 ~ 600 ns |
| RES | > 280 µs | > 280 µs |

**用 WS2812B 的参数配 WS2812C 会花屏** —— 典型后果是 T0H 偏长（被认成 1）。
C 版的 0 码周期（800~1380 ns）与 1 码周期（1160~2000 ns）并不相同，
SPI 是固定位宽，只能取交集，即 **T = 1250 ns**。

### 编码方案：8 MHz + 10 位帧

```
SPI = 32MHz ÷ 4 = 8MHz，1 个 SPI 位 = 125 ns
1 帧 = 10 位 = 1250 ns = 1 个 WS2812 码
```

| 数据 | 10 位波形 | 常量 | T_HIGH | T_LOW |
|---|---|---|---|---|
| **0** | `1100000000` | `0x0300` | **250 ns** | **1000 ns** |
| **1** | `1111100000` | `0x03E0` | **625 ns** | **625 ns** |

四项全部落在手册窗口内。24 码/LED × 10 位 = **240 位 = 30 µs / LED**。

> 为什么 0 码取「2 高 8 低」而不是「3 高 7 低」：边沿变缓时因
> VIH(2.7V=54%)/VIL(0.7V=14%) 不对称，高电平会被拉长约 0.16×(tr+tf)。
> 取 375 ns 加边沿后约 381 ns，会突破 380 ns 上限被误判成 1 码；
> 取 250 ns 加边沿约 256 ns，余量 124 ns。
>
> 为什么 SPI 只用 8 MHz 而不是 16 MHz：本芯片 GPIO 最高翻转能力只有
> 10 MHz（`GPIO_Speed_Level_2`），16 MHz 会让 MOSI 边沿严重变缓。

### 为什么不是 DMA

HK32F030 全系列没有 DMA（四个系列的 SVD 里 DMA 数量都是 0），SPI 的 FIFO
只有 4 层。所以用**阻塞发送**，代价是发送期间占用 CPU —— 2 颗灯约 **60 µs**。

### 用法

```c
WS2812_Init();                          /* 内部会调用 SPI1_Init() */

WS2812_SetPixel(0, 255, 0, 0);          /* 第0颗：红（按 RGB 传，内部转 GRB）*/
WS2812_SetPixel(1, 0, 255, 0);          /* 第1颗：绿 */
WS2812_Show();                          /* 发送整帧 + 自动产生复位脉冲 */

WS2812_Fill(0, 0, 0); WS2812_Show();    /* 全灭 */
```

灯珠数量由 `ws2812.h` 的 `WS2812_LED_MAX`（当前 **2**）控制，改大即可带更多灯。

### 复位处理

发完一帧后连续写入 **256 个 0 码**（每个 10 位全 0 = 1.25 µs），
合计 **320 µs > 280 µs**，把 MOSI 保持在低电平完成锁存。

> 早期版本曾计划「把 MOSI 切成普通 GPIO 拉低」，但那需要在 SPI 复用与
> GPIO 之间来回切，且 SPI 关闭瞬间引脚状态不确定。直接发 0 码更干净。

### 资源占用

| 项目 | 值 |
|---|---|
| 码缓冲 | 2 LED × 24 码 × 2 B = **96 B** |
| 每帧耗时 | 2 颗 ≈ **60 µs** + 复位 320 µs |
| 实测 Code | 3650 B |
| 实测 SRAM | 1228 B（含堆栈各 512 B） |

> 代码尺寸里有一块可以省：`-O2` 会把 `WS2812_Encode` 内联到每个调用点，
> 于是 `main` / `WS2812_Fill` / `WS2812_SetPixel` 各自带一份 24 次循环
> （约 250 B/份）。给 `WS2812_Encode` 加 `__attribute__((noinline))`
> 可以收回约 700 B，需要时再加。
